# Database schema

The local film-engine prototype stores film and checkpoint data in SQLite. It is not the requested production relational schema and has no multi-user authentication. The production schema still needs migrations and ownership, foreign keys, indexes, constraints, retention and access policies for users/profiles/follows, posts/comments/reactions/saves/reports, conversations/messages/notifications, films/versions/scripts/acts/scenes/shots/characters/locations/assets/timelines/render jobs, agent runs/tasks/checkpoints/messages/quality reports, provider connections/resources/contributions/generation jobs/usage/cost estimates, and teams/members/invitations/permissions/audit/subscriptions/credit transactions. Sensitive provider credentials must be encrypted separately with managed keys and never sent to the browser or logs.
