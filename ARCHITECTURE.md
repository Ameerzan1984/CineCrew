# CineMesh architecture

CineMesh builds on the preserved Apache-2.0 CineCrew source (`src/`, configuration, examples, attribution and license). `apps/web` contains Next.js account and workspace routes backed by PostgreSQL; `packages/database/migrations` contains its schema. The web server authenticates users and checks film ownership before calling the internal FastAPI film service with a separate service secret. The film service stores its checkpoint state in SQLite and can validate FilmDSL and invoke CineCrew's offline production-job planner. Keep that database on durable storage; it is not a distributed PostgreSQL queue.

`packages/providers` contains an isolated Higgsfield REST client. Provider API credentials are encrypted per user in PostgreSQL, using a server-side AES-GCM key. Saving credentials is not connection verification. `services/generation-worker` implements independent transactional PostgreSQL scheduling primitives; these are not yet wired into production generation. `services/render-worker` provides limited local FFmpeg concatenation.

This is not a production-ready social network. Do not expose internal services or the development stack to the internet. Production still needs security hardening and deployment, collaborative authorization, social workflows, real AI execution, provider job integration, durable media storage, publishing, monitoring, backups, and end-to-end validation. See DEVELOPMENT_PLAN.md.
