# Higgsfield integration

Reviewed against Higgsfield's current API and MCP OAuth metadata on 2026-10-31. The app contains an API generation path and a per-user MCP OAuth connection, but the web app is not yet a complete multi-user worker and film-rendering pipeline. A separately run local test on 2026-10-31 verified two real API generations and FFmpeg assembly; it did not use the web app, PostgreSQL, two contributors, or a saved CineMesh connection. See [the experiment log](docs/EXPERIMENT_LOG.md).

## Working API path

- Each user pastes the complete `KEY_ID:KEY_SECRET` value into one password field in Connections. The server parses it, encrypts it with AES-256-GCM, and binds the ciphertext to that user's ID. It is never returned to the browser.
- The API key is not verified on save. A successful authenticated generation submission verifies that key for the selected model. The Connections page labels Seedance 2.5 as documented; each user's account access is confirmed only by their own successful request.
- An editor can submit a generation only for a scene they created and only using their own saved credentials. The owner cannot spend a collaborator's key on their behalf. The first enabled model is Seedance 2.5 text-to-video, using a 4-second, 720p, 16:9 MP4 request with audio. Later scenes can use Seedance 2.5 Reference-to-Video with the previous completed clip as a visual reference. Higgsfield still controls the generated result; this does not guarantee exact character identity.
- Each scene request is stored in PostgreSQL with its contributor, model, status and Higgsfield request ID. Its owner polls the provider; the rest of the film team can see the stored status. A request with an ambiguous timeout is marked `uncertain`; the app does not retry it automatically. The contributor must check the Higgsfield dashboard before resolving it and starting another request.
- Completed results initially contain a temporary provider URL. While the contributor's studio is open, it attempts to save a completed video to the private server media volume; an editor can also use the save button if that attempt fails. This browser-driven polling and save is not yet a background worker, and the provider URL is never treated as durable storage. Saved clips receive film-scoped access controls and are streamed by the authenticated media route.

The [Seedance 2.5 text-to-video API reference](https://open.higgsfield.ai/models/bytedance/seedance-2.5/text-to-video/api-reference) documents the first-shot endpoint, request parameters and 4-30 second duration range. The [Reference-to-Video API reference](https://open.higgsfield.ai/models/bytedance/seedance-2.5/reference-to-video/api-reference) documents video-reference inputs for later scenes. The studio now tries to obtain an authenticated USD quote before showing an approval form, then binds that quote to the user, shot, exact prompt, duration, reference and credential before submission. The adapter currently infers `POST /estimate{modelPath}` and a `{usd, credits}` response; that route/schema were not found in the official model API references consulted and have not been verified live. It fails closed on missing or invalid quote data, and mocked estimate tests do not prove provider support. The [Higgsfield quick start](https://open.higgsfield.ai/quick-start) requires the full copied key in one field, says saving alone must not be treated as a successful connection, and warns against blind retries after an ambiguous timeout.

API requests spend from the contributor's separate Higgsfield API USD balance. MCP plan credits are separate. This integration does not retrieve account balance or usage; users can check those in the Higgsfield API dashboard. In the 2026-10-31 test, one generation attempt failed Higgsfield's content-safety check and a later attempt succeeded; actual charges, including for the failed attempt, were not verified in billing. Public prices are estimates, not proof of a user's charge. See the [Higgsfield API account and billing guide](https://higgsfield.ai/creator-hub/help-center/integrations/what-is-the-higgsfield-api).

## MCP

The Connections page can initiate a per-user MCP OAuth connection. Higgsfield's protected-resource metadata advertises `https://clerk.higgsfield.ai` as its authorization server, and the server metadata currently supports authorization-code PKCE (`S256`), public clients, and dynamic registration. The official MCP endpoint is `https://mcp.higgsfield.ai/mcp`. On Connect, CineMesh registers or reuses a user-scoped OAuth client, uses a one-time state and encrypted PKCE verifier, and redirects the user to Higgsfield to authorize. The callback exchanges the code, stores access/refresh tokens encrypted for that CineMesh user, and verifies them with MCP `initialize` and `tools/list`. Token refresh is limited to the OAuth endpoint plus the same read-only MCP verification.

A temporary, user-authorized diagnostic on 2026-10-30 successfully exchanged an OAuth code and listed 187 MCP tools for one Higgsfield account. That account's `generate_video` exposed a nested `params.anyOf` schema including `model`, `prompt`, `duration`, `medias`, and `get_cost`. Its no-charge preflight quoted 35 credits for a 5-second Seedance 2.5 shot. The test account's generation call was refused with `Requires plus plan or higher`; no MCP video job was created. The temporary authorization was revoked and was not saved as a CineMesh connection. This does not establish that other accounts expose identical schemas or that the CineMesh app can submit or resume MCP jobs.

The app does not mark MCP connected until OAuth and tool discovery succeed. This verifies sign-in and tool discovery; CineMesh does not yet submit MCP generation calls from its product UI. Connections retains advertised tool schemas and reports available inputs. A prior [official CLI issue](https://github.com/higgsfield-ai/cli/issues/93), opened on 2026-09-20, reported an opaque generation schema; the current diagnostic account did expose usable fields, but its generation was denied by the plan tier. Do not assume that issue or test account represents every account. Higgsfield's [official CLI guide](https://higgsfield.ai/blog/higgsfield-cli) documents cost preflight and job submission; that CLI is not wired into CineMesh. MCP generation uses Higgsfield plan credits, separate from the API USD balance. MCP balance/usage reads are not surfaced in CineMesh. See Higgsfield's [MCP overview](https://higgsfield.ai/creator-hub/help-center/integrations/what-is-higgsfield-mcp), [agent setup guide](https://higgsfield.ai/creator-hub/help-center/integrations/how-do-i-connect-higgsfield-to-ai-agent), and [API billing guide](https://higgsfield.ai/creator-hub/help-center/integrations/what-is-the-higgsfield-api).

The code and unit tests validate OAuth metadata, PKCE, client registration, token exchange/refresh, encrypted user scoping, read-only verification, and honest schema reporting. The real API experiment used one user's credential through a temporary local form held in process memory; it was not saved in CineMesh. A two-user paid test still requires both people to sign into CineMesh, save separate keys in Connections, collaborate on one film, and approve provider charges for their own shots. A key was pasted in this conversation; rotate it before any later use. Never copy credentials into project memory, issue logs, source, or Git.

## Remaining work

The distributed scheduler is not connected to a trusted Higgsfield worker, and usage/cost reconciliation is not implemented. The media volume is host-persistent when using Compose, but deployments with multiple web instances need shared object storage. FFmpeg was verified on two real clips locally, but the current CineCrew-to-Web-to-Higgsfield-to-stored-film flow has not been exercised end to end. Long feature renders need a background queue, media normalization, retries and storage-budget management. Unit tests mock provider responses and do not spend credits. A real two-user provider generation remains unverified.
