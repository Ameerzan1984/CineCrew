# Development plan

The `cinemesh` branch contains PostgreSQL-backed sessions and film records, editor/viewer roles, attributed scene contributions, CineCrew story-plan import, a per-contributor Higgsfield API route, MCP OAuth discovery, and a local FFmpeg renderer. On 2026-10-31, a separate local diagnostic used CineCrew's `ProductionOperator` to plan two manually authored FilmDSL shots, generated two real Seedance 2.5 API videos using one account (the second referenced the first), and assembled an 8.192-second MP4. This was not an end-to-end CineMesh web-app test. The full CineCrew LLM pipeline and ChatGPT integration were not used. See [project memory](docs/PROJECT_MEMORY.md) and [experiment log](docs/EXPERIMENT_LOG.md).

## Remaining work, in order

1. The Film Engine now supports a dedicated PostgreSQL schema for film data, FilmDSL, agent outputs and checkpoints; SQLite remains the local default. Compose uses PostgreSQL. Hosted CI run [41201209615](https://github.com/Ameerzan1984/CineCrew/actions/runs/41201209615) passed the isolated SQLite import, checkpoint restore across two FastAPI lifespans, and concurrent idempotent advances. Stage completion is atomic and stale runs reconcile saved checkpoints before retry. Still test an actual OS process kill and database backup/restore; worker lease fencing for a process paused past its heartbeat is not implemented, and production multi-replica operation is not verified.
2. Connect the CineCrew generative pipeline—not just `ProductionOperator`—to the film studio: idea/script, Film Bible and asset references, story edit, cinematography, validation, technical direction, review, job planning, checkpoints and resumability. The web app must call a configured language-model provider; the local API test did not call an LLM.
3. Connect saved contributor API credentials and real generation jobs to a reliable worker. Enforce that a contributor can spend only their own provider balance on shots they claim. Persist job state, handle timeouts without blind retries, record consent and reconcile the provider invoice.
4. Keep MCP OAuth as a separate optional path. Live tool discovery worked, but the tested account's MCP generation failed with `Requires plus plan or higher`. Re-test only with an eligible account; support real model/schema discovery, cost preflight, execution, polling and cancellation. Keep MCP plan credits separate from API USD balance.
5. Persist provider media in private durable storage and connect saved clips to the actual film record. Run FFmpeg through a resumable background render job; normalize codecs, aspect ratios, frame rate and audio before concat. Add review, subtitles, audio and explicit publish controls.
6. Migrations 013-016 add private messaging/blocks, audited moderation, film reviews, and one-level threaded replies; hosted PostgreSQL and desktop/mobile evidence is recorded above. Migration 017 now implements owner-scoped public/private film lists, rendered/published visibility filtering, Watch saving and Film lists UI. Local unit/type/build checks pass; hosted PostgreSQL and desktop/mobile checks are pending. Next continue character references, timeline/storyboard editing, general activity notifications, accessibility, backup verification and deployment hardening.
7. Scale only after measured tests: begin with a short scene, then increase shot count and duration. Record quality, continuity, cost, storage, provider failures and recovery time. Do not claim 60–120 minute film production until a full test of that size succeeds.

For implementation sequence and acceptance criteria, use [docs/NEXT_STEPS.md](docs/NEXT_STEPS.md). The developer-agent rules and CineCrew upstream conventions remain in [AGENTS.md](AGENTS.md).
