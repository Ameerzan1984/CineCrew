# Higgsfield language-model access review

Reviewed 2026-10-31 against Higgsfield's published materials. This is a capability assessment, not evidence that a language model has been called from CineMesh.

| Surface | Language-model access and use from CineMesh | Identity, cost and evidence |
|---|---|---|
| Supercomputer | Its interface provides text models and an Auto mode. The reviewed materials do not document a standalone CineMesh inference API for that interface. | Higgsfield says Auto text generation in Supercomputer consumes no credits; this statement does not establish a free external API. Manual models and media may have different costs. No Supercomputer request was made here. |
| Higgsfield-hosted Apps / FNF SDK | The official SDK describes worker-side `createLlmClient`, model discovery, completion, streaming and tool calls inside its supported app environment. No approved external bridge from standalone CineMesh was found. | The platform attaches the visitor's identity and bills credits. Runtime model IDs, structured-output support and actual prices have not been discovered or tested for an account. No hosted companion app or inference was run. |
| Higgsfield MCP | CineMesh supports per-user OAuth and read-only tool discovery. The current connection can expose tool names, descriptions and saved input schemas for inspection. A listed tool alone does not establish that it is a language model or that invocation is permitted. | A historical temporary OAuth test listed 187 tools and quoted a video preflight; video generation was refused by the account's plan. The complete list and a text-model schema were not retained as evidence. Current saved-account text capability, account eligibility, costs and live inference remain unverified. |
| Higgsfield Developer API | Historical testing generated two short videos through the API and assembled them with FFmpeg. The reviewed public sources do not establish a documented language-model inference route for standalone CineMesh. | API billing is separate from MCP plan credits. The exact API USD estimate contract is not verified and paid generation remains disabled in the product. No new provider request was made during this review. |

The official SDK requires runtime model discovery and describes a provider confirmation gate for supported generation flows. CineMesh must preserve the exact provider confirmation and cost semantics before enabling those flows. A CineMesh spending authorization does not replace a provider confirmation token. Structured JSON and vision must be verified for each actual model; neither is inferred from a name. Do not silently switch providers or use an undocumented endpoint.

Sources: [Higgsfield FNF SDK reference](https://github.com/higgsfield-ai/skills/blob/main/higgsfield-websites/references/fnf-sdk.md), [Higgsfield changelog: Auto mode and Apps](https://higgsfield.ai/creator-hub/changelog), [Higgsfield credit rules](https://higgsfield.ai/creator-hub/help-center/credits/how-credits-work), [Higgsfield MCP connection guide](https://higgsfield.ai/creator-hub/help-center/integrations/how-do-i-connect-higgsfield-to-ai-agent), and [existing project experiment log](EXPERIMENT_LOG.md).

Next, use a user's own authorized MCP connection and inspect the saved tool catalog in Connections. A live language request requires an actual advertised and documented text tool with its exact schema, permission and cost understood. A hosted FNF proof of concept requires access to an authorized Higgsfield App environment; do not route an internal service address through the standalone server. Keep other providers explicit and user-selected until a supported integration is verified.

The discovery client now follows MCP tool-list cursors, up to 20 pages and 2,000 tools, and fails closed on duplicate names, repeated cursors or overflow instead of saving a silently truncated listing. This pagination logic has local unit coverage; it has not yet been checked against a live paginated Higgsfield account.
